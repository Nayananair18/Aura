# 🛡️ A.U.R.A. - Authenticity Verification Engine

A.U.R.A. (Authenticity Using Reality Analysis) is a next-generation forensic tool designed to definitively verify whether an image is a genuine photograph taken by a physical camera, or a synthetic image generated by AI (Midjourney, DALL-E, etc.).

Unlike software that relies purely on visual artifacts that AI is rapidly learning to fake, **AURA focuses on Physical Evidence and Multi-Modal Forensics.**

## 🔬 The Physics-First & Multi-Modal Approach

When you take a photograph with a physical camera (like an iPhone or Samsung), the lens and sensor leave behind a distinct, unforgeable physical signature in the image file's metadata (EXIF) and optical noise structure. 

AI models generate pixels, but they **do not** generate the hardware signature of the lens.

AURA uses a multi-engine ensemble to verify authenticity:
1. **Metadata KNN Model**: Analyzes 13 physical hardware points (Camera Manufacturer, Model, Shutter Speed, ISO, Aperture, Focal Length, Flash Data, etc.). If an image lacks a physical camera lens signature, it is immediately flagged as highly suspicious.
2. **Visual CNN Model**: Analyzes pixel-level noise structures, compression blocks, and chromatic aberration.
3. **Groq VLM Vision Engine**: Leverages `groq-sdk` with model `qwen/qwen3.8-27b` to perform parallel deep vision analysis and dedicated screen-replay attack detection.
4. **Screen Recapture & Replay Defense**: Detects optical PWM flicker, subpixel grid interference, and display bezel artifacts. Screen recapture attacks trigger an immediate Priority #1 RED flag (`SCREEN RECAPTURE DETECTED`).

### How it works: "No Physical Proof = Not Verified"
If a user submits an AI-generated image, or an image that has had its physical metadata stripped by social media (like WhatsApp or Instagram), AURA correctly refuses to verify it. AURA requires the original, uncompressed photo straight from a physical device to issue a "Green" Pass.

## 🚀 Features
- **Zero-Adoption Verification**: You can verify ANY image from the internet. You do not need the AURA app installed to take the picture.
- **Physical Evidence Card**: A detailed UI breakdown of exactly which physical hardware signatures were found (or missing) in the uploaded image.
- **Ensemble ML & Groq VLM Engine**: Combines physical metadata KNN analysis, pixel-level deep learning, and parallel Groq VLM vision inspection.
- **Screen Replay Attack Shield**: Automatically catches monitor/TV re-photographing attempts and forces a top-level RED flag override.
- **Ledger Sealing**: Cryptographically hashes images (SHA-256) to ensure they haven't been tampered with post-verification.

## 🛠️ Tech Stack
- **Frontend**: React Native (Expo SDK 54) - Runs on iOS, Android, and Web
- **Backend**: Node.js, Express
- **AI & VLM**: `groq-sdk` (`qwen/qwen3.8-27b` for image analysis & screen replay detection)
- **Database**: MongoDB (Stores Verification Hashes & Reports) + In-Memory Ledger Cache Fallback
- **Machine Learning**: Custom ensemble models (KNN + Logistic Regression weights) implemented natively in Node.js for ultra-fast, edge-capable execution.

## 💻 Getting Started (Local Development)

### Prerequisites
- Node.js (v18+)
- MongoDB connection string
- Groq API Key (`GROQ_API_KEY`)

### Backend Setup
```bash
cd backend
npm install
# Ensure backend/.env contains MONGODB_URI and GROQ_API_KEY=gsk_...
npm run dev
```
The backend will run on `http://localhost:3001` (and be accessible on your local network).

### Frontend Setup
```bash
cd frontend
npm install
```
Ensure your `frontend/.env` file points to your backend. To test on a physical device, set `EXPO_PUBLIC_API_BASE_URL` to your PC's local IP address.
```bash
# Start the web preview
npx expo start --web

# Start for mobile testing (scan QR with Expo Go)
npx expo start -c
```

## 📱 Building the App
AURA can be built into a standalone APK/AAB or IPA using Expo Application Services (EAS).
```bash
cd frontend
npx eas build -p android --profile preview
```
*Note: Make sure your `.env` is pointing to your production backend URL before running a production build!*
